# Native iPhone and iPad user scenarios

Issue #36 uses a standalone XCTest UI bundle against the supplied app. It never builds Kotlin, resets the app container, or calls an editor test hook. Android shares `fixtures/user-scenarios` and the literal XML verifier, while platform executions and reports remain separate.

Run `python3 scripts/run-ios-e2e.py --simulator UUID --app /absolute/path/LogisimMobile.app --baseline-sha SOURCE_COMMIT --output outputs/ios-e2e/UNIQUE_RUN` after reserving that booted Simulator. Every attempt requires a fresh output directory. `--derived-data PATH` reuses compilation only.

`--build-lock DIR` acquires a host-wide `mkdir` lock (for example `/tmp/logisim-build.lock`) only around the harness `build-for-testing` step and always releases it; scenario execution runs without the lock. `--prepare-only` creates the test project without device actions. `--build-only` does not run cases. `--only-testing Target/Class/Method` selects partial coverage. `--alpha` records ALPHA_ONLY even when selected cases pass. The declared source revision and the actual executable/bundle fingerprints are recorded separately; a source identity is not inferred from the binary.

Large XML copies use a test-only UIKit app, `thalesmms.logisim.validation.clipboardreceiver`. After the production Copy action updates the pasteboard revision, the scenario activates that app, taps its visible Clear and system `UIPasteControl`, reads the resulting UITextView accessibility value, and reactivates the existing Logisim process. The receiver performs no automatic pasteboard read and changes no production code. The runner builds, fingerprints and installs the receiver explicitly; a UI-test target with an empty host does not install it automatically. This flow respects the iOS foreground paste permission that rejects a direct `UIPasteboard.string` read by the XCTest runner.

The runner verifies that the JSON resources exist inside the built XCTest bundle before executing scenarios. Each run stages only its own files in `Documents/LogisimE2E/<run-id>`, with unique circuit names. No unrelated workspace or document is removed.

Evidence includes xcresults, exported XCTest attachments, simulator logs, a final screenshot, exact circuit inputs and the saved external file. Compare an observed XML file with `python3 scripts/user_scenario_contract.py --document PATH --checkpoint CHECKPOINT --output OUTPUT`.

Cold and warm Open With use public `XCUIDevice.shared.system.open`. The warm case does not call launch between documents. Cancellation waits for UIKit Cancel/Close and requires the native controller to disappear. Background canvas existence is insufficient. UIKit's PopoverDismissRegion extends beyond the display, so dismissal touches use the observed application frame.
