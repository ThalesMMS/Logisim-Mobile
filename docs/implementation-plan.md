# Parity epic implementation

Completing an issue requires meeting its acceptance criteria, running the relevant tests, and integrating the work in the app. Closing out an entire family requires evidence specific to that family.

## Sequence

1. Publish the validated SAP-1 implementation.
2. Establish an extensible registry and contracts for attributes, ports, and execution.
3. Implement component and tool families in separate worktrees.
4. Integrate each validated issue, publish its commit, and verify the result on the remote.
5. Validate Android and iOS workflows, data, accessibility, performance, and distribution.

Only the integrator writes to the main branch. Each worker commits locally on their own branch. Coordinate builds that share compilers and simulators. Document distribution and external integration decisions explicitly and track unavailable integrations as outstanding.

The per-issue record goes in `implementation-decisions.tsv`. The [parity matrix](parity.md), generated by `scripts/parity_matrix.py`, remains the reference for support.
