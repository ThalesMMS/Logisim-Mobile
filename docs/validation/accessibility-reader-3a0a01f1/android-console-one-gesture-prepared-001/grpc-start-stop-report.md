# Console gRPC startup and rollback boundary

Conclusion: the inspected public interfaces do not establish a reversible way to start only a loopback, existing-auth gRPC endpoint and stop it again while preserving the running AVD. A safe endpoint-only teardown is missing from these interfaces. This is source research against QEMU commit `686efa16baf59d776cadc3f975d12570fe44bbb9`; the installed Emulator 37.1.11 binary was not inspected or exercised. No local VM/console/RPC/GUI/build, credential, process-argument or environment operation occurred.

## Startup chain and port zero

Console top-level `grpc <port>` accepts integers 0..65535 and calls `grpc_agent->start(port, "")`. [console.cpp4126–4152](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android/android-emu/android/console.cpp#4126). In this commit, the bound `start_grpc` ignores both parameters and calls `qemu_setup_grpc()` without them. Therefore console `grpc 0` is neither a stop command nor proof that a fresh ephemeral port was requested. [qemu-grpc-agent-impl.cpp19–25](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android-qemu2-glue/qemu-grpc-agent-impl.cpp#19).

`qemu_setup_grpc()` returns the existing service port if one already exists. For a new service, it reads the original startup options. Its initial bind is `[::1]` and its port range starts at serial+3000 with exclusive end serial+4000. An original `-grpc` option substitutes that option's port and initial wildcard `[::]` address. The console argument does not choose the address or auth policy. [qemu-setup.cpp312–367](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android-qemu2-glue/qemu-setup.cpp#312).

The final builder policy matters: token/JWT with an otherwise insecure transport forces loopback/local credentials. TLS with an original wildcard bind is not converted by that branch. Loopback is translated to the selected IPv4/IPv6 family before binding. Consequently the console command alone does not prove the final bind. [GrpcServices.cpp284–333](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android/android-grpc/android/emulation/control/GrpcServices.cpp#284).

## Authentication is selected from original options

TLS uses the configured original certificate/private-key/CA paths. Legacy token mode generates a new random bearer token. JWT mode creates a new per-PID UUID directory and active-key path; this startup function does not import an old signer or old trust directory. These are new service/authentication-state effects, not merely a read of an existing endpoint. When both token and JWT are absent, no bearer/JWT interceptor is installed; configured TLS or mutual TLS is a separate transport-authentication mechanism. [qemu-setup.cpp388–408](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android-qemu2-glue/qemu-setup.cpp#388), [GrpcServices.cpp170–200 and294–321](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android/android-grpc/android/emulation/control/GrpcServices.cpp#170).

Startup also writes advertising metadata. A failed builder can leave earlier startup effects such as a newly created JWT directory; for some original explicitly requested gRPC configurations, failure calls `exit(1)`. No read-only or no-AVD-impact guarantee follows from the console accepting the command. [qemu-setup.cpp433–479](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android-qemu2-glue/qemu-setup.cpp#433).

## Teardown and observability

The internal C++ controller has `stop()`, implemented as server shutdown with a 500ms deadline. [GrpcServices.cpp69–90](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android/android-grpc/android/emulation/control/GrpcServices.cpp#69). However, the exposed QGrpcAgent has only `start` and `active_port`; the inspected console table and controller protobuf have no endpoint-only stop command. [grpc_agent.h19–24](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android/emu/agents/include/android/emulation/control/grpc_agent.h#19).

The demonstrated call that stops and resets the global service, then removes advertising, belongs to `qemu_android_emulation_teardown()`, alongside global emulation and snapshot finalization. It is not a public endpoint-only rollback. [qemu-setup.cpp603–620](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android-qemu2-glue/qemu-setup.cpp#603). Idle timeout is documented to shut down the emulator; its implementation first calls vmShutdown and later killProcess, so it is not a substitute. [GrpcServices.h119–122](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android/android-grpc/android/emulation/control/GrpcServices.h#119), [IdleInterceptor.cpp65–84](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android/android-grpc/android/emulation/control/interceptor/IdleInterceptor.cpp#65).

The public active-port getter and PID/listener inventory can observe endpoint state. They do not provide the missing teardown operation or prove authentication/advertising state was restored. This research does not authorize startup, a key publication, a secret read or any attempt to discover undocumented behavior in the installed binary.
