# Emulator endpoint discovery and authentication boundaries

This report is public-source research only. No local emulator, device, console, RPC, process arguments, environment or credential file was queried. Sources are pinned to QEMU commit `686efa16baf59d776cadc3f975d12570fe44bbb9`. That commit is not claimed to match the installed Emulator 37.1.11 binary. Downloaded text and SHA-256 values are retained beside this report.

## Prefer the public console getter for exact port attribution

The console has two different commands with materially different effects:

- `avd grpc` is a getter. `do_avd_grpc_port` calls `grpc_agent->active_port()` and prints the active port or returns an explicit failure if no service is active. It is registered both in normal `avd` commands and in the pre-auth command set. [console.cpp lines 2698–2706, 2882–2884, 4536–4538](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android/android-emu/android/console.cpp#2698).
- Top-level `grpc <port>` calls `start` and is mutating. It must not be substituted for the getter. [console.cpp lines 4126–4152 and 4381–4383](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android/android-emu/android/console.cpp#4126).

The getter's agent binding is direct: `active_port = &qemu_grpc_port`. [qemu-grpc-agent-impl.cpp lines 16–25](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android-qemu2-glue/qemu-grpc-agent-impl.cpp#16). `qemu_grpc_port()` only returns the existing `grpcService->port()` or `-1`. [qemu-setup.cpp lines 304–309](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android-qemu2-glue/qemu-setup.cpp#304).

A coordinator-authorized `adb -s emulator-5556 emu avd grpc` can therefore identify the endpoint without our code opening the discovery INI or inspecting secrets. This source review did not audit whether the adb client internally reads its console authentication token. Parse only one decimal port plus the console terminator, validate 1..65535, and cross-check that the same current PID owns a loopback listener on that port and the console name matches the reserved AVD. No match, no active service, extra/ambiguous response or PID drift must fail. Do not use a default 8554 or select the first emulator. This report did not run the getter and does not identify any of the reported local listeners as gRPC.

## Discovery locations and schema

The pinned C++ implementation selects `HOME/Library/Caches/TemporaryItems/avd/running` on Darwin. If its discovery root environment key is absent, it uses the emulator user directory and appends `avd/running`. [ConfigDirs.cpp lines 298–349](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android/emu/files/src/android/emulation/ConfigDirs.cpp#298). The fallback user directory checks `ANDROID_EMULATOR_HOME`, `ANDROID_PREFS_ROOT`, the deprecated `ANDROID_SDK_HOME`, and home/temp fallbacks. [ConfigDirs.cpp lines 58–89](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android/emu/files/src/android/emulation/ConfigDirs.cpp#58).

The Python discovery sample searches `pid_<PID>.ini` and additional configurable user roots, including `ANDROID_AVD_HOME`. [emulator_discovery.py lines 30–62 and 88–125](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android/android-grpc/python/src/aemu/discovery/emulator_discovery.py#30). The older README mentions `pid_<PID>_info.ini`, which differs from the executable sample's pattern. Do not assume that old prose names the installed binary's exact metadata file.

The advertised schema mixes public and sensitive values in the same INI. `qemu_setup_grpc()` adds serial/ADB ports and AVD name/ID/directory, but also `cmdline`. It adds inline `grpc.token` for legacy bearer mode, JWT directory paths in `grpc.jwks` and `grpc.jwk_active`, and `grpc.port` for the built service. [qemu-setup.cpp lines 318–324, 388–408 and 433–454](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android-qemu2-glue/qemu-setup.cpp#318).

A filename/stat-only inventory can establish file existence and ownership without opening its contents. It cannot establish which inline auth keys exist. Before explicit secret-read approval, do not read or copy the whole discovery INI just to get the port. Use the console getter. Missing directories do not prove that no gRPC server exists. They may reflect a different launch root, source-version drift or registration state; this report did not inspect the local environment to distinguish those cases.

## Do not invoke the official discovery client unchanged

The Python parser reads every value into a dictionary, including `cmdline` and any token. [emulator_discovery.py lines 53–63](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android/android-grpc/python/src/aemu/discovery/emulator_discovery.py#53). Its channel helper defaults to port 8554 if none is present and chooses basic token mode before JWT mode. [emulator_description.py lines 40–85](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android/android-grpc/python/src/aemu/discovery/emulator_description.py#40).

The JWT branch is not read-only. It constructs `JwtKeygen`, generates a signing key, writes a new public JWK to the emulator's watched directory, waits for the active-key file, and removes its own JWK in the destructor. [interceptor lines 66–84](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android/android-grpc/python/src/aemu/discovery/header_manipulator_client_interceptor.py#66), [jwt_keygen.py lines 78–92 and 116–144](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android/android-grpc/python/src/aemu/discovery/jwt_keygen.py#78). Existing public verification JWKs alone do not provide a private signer. Do not create or publish a key under a read-only authorization.

The sample package requires grpcio, protobuf, six and Tink. Its setup script can install grpcio-tools and compile protobufs during setup. Merely preparing a client must not execute that setup under a no-install scope. [setup.py lines 37–68 and 163–167](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android/android-grpc/python/setup.py#37). Source availability is not evidence that those packages or a compatible generated client are installed locally.

## Proposed two-phase parser and auth plan

Phase one remains secret-free. Parse the public console getter response and correlate PID/listener/AVD identity. Check only known metadata and auth-path existence with stat if needed. Keep auth mode `UNKNOWN` if identifying it would require opening the mixed discovery file. Do not inspect process arguments or environment variables.

Phase two requires explicit approval of a concrete credential source and client. Only then may a bounded, non-following, owner-validated file reader load the required credential into process memory. It should retain only approved public fields for receipts, always discard `cmdline`, never print the INI, token, signing key, authorization metadata or a hash of a secret. It must not serialize arbitrary exceptions that might include request or credential text. Record only typed failures, authentication mode and a boolean credential-loaded state. A TLS root certificate is public, but private key bytes remain secret. A missing compatible credential or signer stops the preparation rather than causing a new key, server, auth mode or transport to be created automatically.

For JWT, a separately approved temporary key/publication/cleanup unit would be required if no existing authorized signer is available. The official helper's automatic publication is a mutation even though the published JWK is public. A bearer-token branch can keep the existing token only in memory and set the authorization metadata directly. The inspected API uses bearer metadata for both token and JWT, so header shape alone does not identify the mode. [Security README](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android/android-grpc/docs/README.md#13).

## Touch identifier and cleanup correction

The logical API identifier `28` is valid and is mapped to an internal free slot; it is not slot 28. The pinned sender uses slots 0..9 because `MTS_POINTERS_NUM` is 10, even though the observed guest capabilities reported 0..10. Its Linux tracking ID is the selected slot, not the external identifier. A future trace must discover that mapping and require tracking `-1` on the same slot. Pressure zero on the same logical identifier removes the contact mapping.

The default 120-second expiration is checked only when another `doSend` call arrives. Waiting for 120 seconds is not a guaranteed contact-release timer. The explicit pressure-zero `finally` release, bounded recovery and observed contact termination remain necessary. These limits are independently reviewed in the separate touch-identifier report and source hashes. Primary references are [TouchEventSender.cpp lines 113–181](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android/android-grpc/android/emulation/control/keyboard/TouchEventSender.cpp#113), [its expiration loop at 84–111](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android/android-grpc/android/emulation/control/keyboard/TouchEventSender.cpp#84), and [TouchEventSender.h lines 32–47](https://android.googlesource.com/platform/external/qemu/+/686efa16baf59d776cadc3f975d12570fe44bbb9/android/android-grpc/android/emulation/control/keyboard/TouchEventSender.h#32).

No new reader attempt, auth read, client setup, endpoint connection or hardware input occurred during this research.
