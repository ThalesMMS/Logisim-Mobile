## Prepared client and authentication boundary

`getter-status.mjs` uses installed Node 26.10 HTTP/2 and protoc 36.2. No Python gRPC package is installed in the three checked interpreters. The prepared descriptor comes from the exact installed SDK proto, SHA-256 `1d62c6bcad5f06621f90ec2bf26c661ba769ccd0f1416b5314d25a68e04eee5f`; the decoder checks its frozen descriptor hash. The client has no mutable RPC method or gesture function. Its CLI supports discovery only, and does not perform a getter RPC by default.

The getter API requires a recent, explicit-serial PID/loopback-port/proto proof before calling any credential loader. It permits only the hardcoded `EmulatorController/getStatus` unary request, a five-second transport deadline, a bounded uncompressed unary response and the frozen descriptor. The native HTTP/2 transport is internal. No default credential loader is supplied because no live endpoint or credential source has been identified.

A future approved loader must read only the exact existing credential source into the client process and send it only to the attributed loopback endpoint. It must not create keys, publish JWKs, use environment credentials or choose another emulator. The result may record the approved source path, existing bearer type and presence, with the authorization header redacted. It must never record the credential value or hash, JWT claims, raw upstream errors, response headers or decoded configuration. The decoder returns only numeric version, booted state and numeric uptime. No actual secret has been used to test this client.

Independent review found that clearing NODE_DEBUG after Node startup did not disable an already initialized HTTP/2 logger. The client now checks `debuglog('http2').enabled` before the credential loader and refuses to run when active. A child-process reproduction started with HTTP/2 debug proves the loader is never called. Review also found that exporting the raw transport bypassed the proof gate; the transport is now internal. These were preparation defects, found before a real credential or controller connection.

Eleven offline tests cover protocol KO, mismatched/unbound/stale endpoint proof, unary framing, a literal protobuf response decoded through the real descriptor, redacted results, reflected error strings, invalid credentials, credential-reader errors and startup protocol debug. Independent review additionally exercised default transport success, nonzero gRPC status and deadline with an entirely fake HTTP/2 connection, confirming cleanup in all three cases. No fake opened a socket. These tests do not qualify live gRPC, actual authentication, delivery to the guest or TalkBack.

The future concrete credential loader and its driver still need their own bounded deadline before any real credential is used. The prepared transport's five-second timer begins after the loader; it is not a total-operation timeout and cannot cancel an arbitrary pending loader. No live loader or executable authenticated runner is supplied here. The absent endpoint is an additional prerequisite. This source is approved as preparation only.

## Contact identifier correction

The SDK field `Touch.identifier` accepts an arbitrary nonnegative logical ID. ID 28 is valid; it does not select Linux slot 28. The reviewed public sender maps it to one of ten internal slots, 0 through 9, while the actual guest advertises 0 through 10. Its Linux tracking ID follows the allocated slot. A future passive trace must correlate that actual slot and its tracking -1 release, not search for tracking ID 28. The map is not namespaced by client, so exclusive ownership and no conflicting active identifier are preconditions. [Pinned source findings](touch-identifier-source-research.md).

The default 120-second expiration is checked only when another event arrives. It is not a timer-driven release guarantee. Explicit pressure zero for the same logical ID, bounded cleanup, and evidence of contact termination remain mandatory. The earlier [one-gesture plan](../android-console-capabilities-5556-001/next-transport-plan.md) now reflects these limits and the absent endpoint. No gesture is authorized by this preparation.
