## Keep the reader running while observing it

Android's UiAutomation normally suppresses accessibility services. Its documented `FLAG_DONT_SUPPRESS_ACCESSIBILITY_SERVICES` preserves them. [API reference](https://developer.android.com/reference/android/app/UiAutomation#FLAG_DONT_SUPPRESS_ACCESSIBILITY_SERVICES).

At this product pin:

- `UiSnapshotInstrumentation.java:85` and `UiSnapshotSeriesInstrumentation.java:75` request that flag. The snapshot writer also distinguishes `accessibility-focused` from keyboard/input `focused` at lines 306–307.
- `AndroidUi.screen()` routes ordinary observations through `uiautomator dump`. Its SDK-only route is conditional on field-focus state. It must not be used unchanged as the observer throughout a TalkBack campaign.
- `NativeMixedInput.java:58` and `MixedInputScenarios.kt:39` obtain UiAutomation without this flag. Do not run those instrumentations during the reader phase.

These are source findings, not an observation that TalkBack was suppressed locally. The prepared opt-in client in original commit `96a59ba4b1dcf37ceb97ccabd6f5a34d9d759994` supplies this route through `AndroidUi(..., preserve_accessibility_services=True)`. It requires an isolated `.e2e` package, always uses the non-suppressing SDK capture for app checkpoints, and rejects an external/missing foreground without CLI fallback. The default client behavior is unchanged. Thirteen new boundary tests and 67 existing focus/UI/census tests passed offline, with real subprocess access blocked. The later stopped Android unit used this observer with TalkBack enabled through Settings, but did not retain live bound-service/touch-exploration state around captures and did not qualify gesture/speech handling. Its PID check covers each capture and its retries, not continuity across separate `screen()` calls. Preserve the existing nonce/package/PID/completeness validation and capture deadlines. A system-owned TalkBack menu may need a screenshot rather than an app-root capture. A capture failure remains a failure; it must not trigger a different observer that disconnects the reader.

Before qualifying the observer, record the service as running before and after a capture, retain the same focused node and obtain a new spoken phrase following the next gesture. A secure setting that lists the service alone does not show that it is currently processing input.

## Smallest next Android unit: TalkBack handoff and one action

Reserve exactly one returned Android lane and the immutable isolated `.e2e` APK plus its matching observer APK. Record source and artifact hashes and verify installed bytes before and after the run. Any installation needs separate authorization. No other lane is needed. Preserve the current workspace before setup.

1. **Preflight.** Record serial, OS/API, logical window/density, locale, font scale, rotation, app/helper hashes, TalkBack package/version, running service, IME and original reader/developer settings. If required, load the built-in SAP-1 through the public UI before starting the reader phase. Mark that fixture setup separately; it proves no reader creation flow.
2. **Reader setup.** Enable developer speech display while TalkBack is disabled, retaining screenshots before and after. Then enable TalkBack through its Settings UI. Preserve the existing log verbosity, shortcuts and gesture mappings. Google documents those diagnostics. Preserve raw logs without assuming a stable log tag or complete speech transcript. [Android testing](https://developer.android.com/guide/topics/ui/accessibility/testing).
3. **Transport check.** Use the installed reader's configured next/previous gesture twice. Each must change the accessibility-focused element and produce the corresponding TalkBack phrase. Activate one focused item using the reader's double-tap. If the emulator gesture transport does not work, stop with the actual failed evidence. Do not substitute direct semantic clicks, `setText` or `performAction`.
4. **Enter the app route.** Reach Project tools and Circuit explorer through reader navigation, including a real overflow menu if present. The existing Explorer is the nonspatial route; this plan adds no permanent entry or alternative presentation. Require the spoken destination and resulting mounted panel after each activation.
5. **One interactive input.** Locate the SAP-1 `Reset` input through the reader. Confirm its identity, kind and current known value. Open the reader's Actions menu and choose the named Activate action. Observe a changed value through TalkBack, then activate again and observe the original value. If the fixture does not offer a stable toggle input, fail the stated precondition rather than silently choosing another component.
6. **Finish.** Preserve the gesture timeline, continuous speech-display video, screenshots and complete app snapshots at the relevant checkpoints. Restore the input and all reader/font/rotation/IME/developer settings, verify the restored state and return the lane. Record restoration failures separately.

Google describes linear navigation and focused activation separately from inspection tools. Its menu documentation explains how to open the TalkBack menu and that Actions depend on the focused item. Confirm the actual installed gesture mapping; these defaults are not a local transport result. [Android testing](https://developer.android.com/guide/topics/ui/accessibility/testing), [TalkBack menu](https://support.google.com/accessibility/android/answer/6007066?hl=en).

The machine-readable contract in `reader-contract.json` defines this unit's evidence requirements. It is a plan, not an executable runner or a result. A pass would qualify only the stated reader handoff/action on that artifact.

## Follow with creation, simulation and saving

After the first unit passes, use a separate run to create a named empty workspace project through Workspace → New project. Open the existing Explorer Insert dialog, enter grid positions and insert two inputs, AND and output. Use the software keyboard with the reader to label them `A`, `B` and `Y`. Then connect named terminals through Start connection/Connect to, inspect the wires and read values for `00→0`, `10→0`, `11→1`, `01→0`. Use Edit and Remove through the reader, then Undo to restore the exact component IDs and connectivity.

Record the actual software IME and enter text through its TalkBack interaction. Google's Gboard instructions use touch exploration and release to type; other IMEs need their own observed behavior. A successful programmatic text replacement is a different test. [TalkBack navigation and text entry](https://support.google.com/accessibility/android/answer/6006598?hl=en).

Save a copy through the app and native document picker using the reader throughout, then restart the app and reopen it through the reader. An independent XML oracle must compare labels, IDs, four components, named-terminal connectivity and the four truth-table outputs. A readable internal workspace snapshot supplements the user-visible save/reopen steps; it cannot replace them. Stop and retain failures in system picker controls as part of the same workflow.

Use another run for RUN/Pause announcements and a continuous ten-second speech-display recording. Keep automatic value refresh disabled initially, then explicitly test it. Count only utterances actually retained in video/logs; sampled screenshots do not prove that a speech queue stayed quiet between samples. Verify focus before and after pause, modal close and rotation. Do not equate keyboard/input focus with the reader's accessibility focus.

Repeat the applicable workflow at the largest supported Android text size and in both orientations, retaining actual dimensions and safe/IME rectangles. Measure rendered contrast and targets separately, including the app's high-contrast signal option. Keep an unfiltered audit for every examined screen and menu. On iOS, extend the now-passing service capability probe to reader target identity, activation and workflow speech assertions, retaining the separate native tree, text-size, focus and unfiltered audit matrix. Finally perform the reader workflow on physical iPhone and iPad.
