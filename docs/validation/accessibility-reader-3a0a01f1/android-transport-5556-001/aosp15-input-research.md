# Android 15 shell swipe and accessibility input filtering

This is read-only source research against the AOSP tag `android-15.0.0_r1`. No device query, reader operation, GUI, build, patch or further gesture was performed. Public text sources were fetched from android.googlesource.com; local copies are retained beside this report.

## Source findings

1. [InputShellCommand.java, lines 496–530](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-15.0.0_r1/services/core/java/com/android/server/input/InputShellCommand.java#496) implements `swipe` as one-pointer DOWN, interpolated MOVE events and UP. Lines 211–238 construct the MotionEvent and use WAIT_FOR_FINISH. Lines 137–138 send it through `InputManagerGlobal.injectInputEvent`.
2. [InputManagerGlobal.java, lines 1378–1398](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-15.0.0_r1/core/java/android/hardware/input/InputManagerGlobal.java#1378) forwards the request through the input manager Binder service. [InputManagerService.java, lines 884–907](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-15.0.0_r1/services/core/java/com/android/server/input/InputManagerService.java#884) checks INJECT_EVENTS and calls native injection with FLAG_DISABLE_KEY_REPEAT.
3. [JNI bridge, lines 1955–1984](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-15.0.0_r1/services/core/jni/com_android_server_input_InputManagerService.cpp#1955) sends the MotionEvent directly to `InputDispatcher::injectInputEvent`.
4. [InputDispatcher.cpp, lines 4777–4806](https://android.googlesource.com/platform/frameworks/native/+/refs/tags/android-15.0.0_r1/services/inputflinger/dispatcher/InputDispatcher.cpp#4777) adds POLICY_FLAG_INJECTED and POLICY_FLAG_TRUSTED. The motion branch at 4858–4940 invokes the pre-queue policy when not already FILTERED, constructs MotionEntry and queues it. Lines 4974–4980 enqueue those entries directly. This path does not call `filterInputEvent`.
5. The separate [notifyMotion path, lines 4625–4645](https://android.googlesource.com/platform/frameworks/native/+/refs/tags/android-15.0.0_r1/services/inputflinger/dispatcher/InputDispatcher.cpp#4625) calls `filterInputEvent` when the input filter is enabled. [InputFilter.java, lines 26–46](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-15.0.0_r1/core/java/android/view/InputFilter.java#26) explicitly documents that device-generated events enter the filter and externally injected events do not.
6. [Input.h, lines 333–346](https://android.googlesource.com/platform/frameworks/native/+/refs/tags/android-15.0.0_r1/include/input/Input.h#333) distinguishes INJECTED, TRUSTED, FILTERED and INJECTED_FROM_ACCESSIBILITY. FILTERED means an event has already passed through the filter. It is not a request to apply the filter. [InputManagerService.java, lines 2880–2892](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-15.0.0_r1/services/core/java/com/android/server/input/InputManagerService.java#2880) reinjects a filter's output with FLAG_FILTERED.
7. [AccessibilityInputFilter.java, lines 656–672](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-15.0.0_r1/services/accessibility/java/com/android/server/accessibility/AccessibilityInputFilter.java#656) adds TouchExplorer only when the touch-exploration feature is enabled. [TouchExplorer.java, lines 266–292](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-15.0.0_r1/services/accessibility/java/com/android/server/accessibility/gestures/TouchExplorer.java#266) handles touchscreen-source motion and feeds gesture detection. Merely selecting SOURCE_TOUCHSCREEN in a shell injection does not route the event through notifyMotion or that filter.

The native pre-queue policy is distinct from the accessibility input filter. [NativeInputManager::interceptMotionBeforeQueueing, lines 1479–1498](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-15.0.0_r1/services/core/jni/com_android_server_input_InputManagerService.cpp#1479) sets PASS_TO_USER for injected events while interactive and returns; it is not the filter call.

## Limited conclusion

In the inspected AOSP Android 15 tag, `adb shell input touchscreen swipe` uses an injection path that bypasses InputFilter, including the TouchExplorer transformation installed there. A successful shell command is not proof that TalkBack recognized a navigation gesture.

For the observed Google Android 15 AVD run, this source behavior is a plausible explanation for direct canvas panning. That is an inference, not a trace of the installed system. The run did not retain the bound-service state or touchExplorationEnabled while TalkBack was on. The focused Canvas node and the reader speech-display caption retained in the video do not establish that the swipe passed through the reader. The caption is positive evidence of reader-produced text for Canvas, but the video has no audio stream and does not fill the service-state gap.

The reviewed tag is not claimed to be byte-identical to the Google AVD system image. No conclusion about a product accessibility defect, reader failure, gesture configuration, alternate transport or permission workaround follows from this research alone. A future transport qualification must be a separate authorized unit with actual service and reader-output observations.
