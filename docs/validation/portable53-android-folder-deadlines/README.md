# Android portable folder navigation deadlines

Attempt 8264 imported the explicitly granted source folder and displayed outputs 8 and 3. It failed in native location navigation during the first export. No completed export from this attempt is counted as an app export. The original run, frozen scripts, screenshots, workspace archives and diagnostics are preserved in `failed-8264`.

The old helper used one 30 second deadline across presentation, opening roots, choosing a location and entering Download. Its nested file selection also created a separate deadline before returning to the older one. This structure can reject a later transition without giving it time after its action. The original logs do not record per-phase timestamps, so this is a code-level cause that the new negative controls reproduce, not a measured attribution for attempt 8264.

The revised helper allows 30 seconds per transition and a fixed 90 second total, with at most three navigation taps. The total possible duration therefore increases from the previous shared 30 seconds. It never resets a deadline on a poll, forwards the remaining limit to blocking queries and taps, and refuses readiness observed after a deadline. Every invocation writes a JSON trace with phase, elapsed time, action count and query durations. The direct Downloads route and the device-storage route share this policy. File bytes, grants, workspace freshness, source archives and the export/restart/desktop checks are unchanged.

Offline checks passed: 21 navigation tests, 10 fixture preparation tests, 11 APK preflight tests and 5 reset lifecycle tests. Negative controls cover each readiness phase, a late tap, a late device-model query, an overall deadline reached while each transition is still within its individual limit, and an unrelated Download row outside the native list. No Android process or device is used by those tests. A new native run is required after independent review and canonical integration. This correction makes no performance claim.
