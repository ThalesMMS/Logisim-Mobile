## Documented meaning and diagnostic limit

Apple describes `providerNotFound` as the manager being unable to find the provider. Its development guidance is to check that the app contains a File Provider extension. For deployed apps, it also discusses system registration still pending and waiting for a domain-change notification. Those are documented possibilities, not an established explanation for B25. No retry was performed. [Apple: providerNotFound](https://developer.apple.com/documentation/fileprovider/nsfileprovidererror/code/providernotfound)

Apple's March 2024 updates distinguish underlying errors for a temporarily unavailable domain, an unregistered domain and a missing app extension. The SDK 27.2 headers name these `providerDomainTemporarilyUnavailable` (`-2012`), `providerDomainNotFound` (`-2013`) and `applicationExtensionNotFound` (`-2014`), available on iOS 17.1. [Apple: File Provider updates](https://developer.apple.com/documentation/updates/fileprovider)

The built [store source](ios-fileprovider-bootstrap-failures-2026-11-05/evidence/002/fixture-source/Shared/FixtureStore.swift) records only NSError domain/code; the [control app](ios-fileprovider-bootstrap-failures-2026-11-05/evidence/002/fixture-source/ControlApp/RevocationFixtureApp.swift) adds `localizedDescription` to the visible status. The archived snapshot contains no NSError chain or `NSUnderlyingErrorKey`. We therefore cannot determine whether an underlying error was supplied or which state it would have identified. The visible message is not enough to choose one.

## Bundle, principal class and API comparison

Apple's domain-registration API accepts a domain and completion handler; the manager initializer also accepts a domain. Neither signature exposes a bundle-selector argument. `providerIdentifier` is documented as a coordination purpose identifier that returns the containing app's bundle identifier; it is not documented as a selection override. The local manager header permits use from the containing app and its extension. Fixture source `48412de3` calls `add` from that containing app with its explicit replicated domain. [Apple: add](https://developer.apple.com/documentation/fileprovider/nsfileprovidermanager/add(_:completionhandler:)), [init(for:)](https://developer.apple.com/documentation/fileprovider/nsfileprovidermanager/init(for:)), [providerIdentifier](https://developer.apple.com/documentation/fileprovider/nsfileprovidermanager/provideridentifier)

`NSExtensionPrincipalClass` identifies the extension's implementation class. Apple states that including it together with `NSExtensionMainStoryboard` prevents loading. [Apple: NSExtensionPrincipalClass](https://developer.apple.com/documentation/bundleresources/information-property-list/nsextension/nsextensionprincipalclass)

The existing signed artifact contains `RevocationFixture.app/PlugIns/RevocationProvider.appex`. Its **compiled** Info.plist resolves the principal to `RevocationProvider.RevocationFileProvider`, matching the source class and module, and contains no storyboard key. It declares `com.apple.fileprovider-nonui`, enumeration support and the same document group as the entitlements. The extension bundle ID is the app ID plus `.provider`; minimum OS is 17.0. These are reads of an archived build, not of a live installed bundle or extension registry. The four extension keys match the [local template census](ios-fileprovider-bootstrap-failures-2026-11-05/primary-local-extracts.txt). No demonstrated mismatch in these declarations explains the callback.

## App Group and signature comparison

Apple documents App Groups as sharing containers between apps and extensions from the same team, and requires group registration for iOS/iPadOS apps. It distinguishes configured entitlement files from the entitlements embedded in a signed executable and their provisioning authorization. [Apple: Configuring app groups](https://developer.apple.com/documentation/xcode/configuring-app-groups), [Entitlements](https://developer.apple.com/documentation/bundleresources/entitlements), [Diagnosing Issues with Entitlements](https://developer.apple.com/documentation/bundleresources/diagnosing-issues-with-entitlements)

The archived effective entitlements for both products contain exactly `group.thalesmms.logisim.validation.revocationfixture`. The signature logs report `Signature=adhoc` and `TeamIdentifier=not set`; the archived products contain no embedded provisioning profile. These are facts about the isolated Simulator artifact. The successful Prepare and public snapshot establish the control app's own storage access. They do not prove the extension's access, team-authorized deployment, or provider registration eligibility. The consulted documentation does not establish ad-hoc signing as the cause of this callback on this Simulator.
