# Real JFR privacy smoke

This unit validates the restricted JFC profile and the Java environment contract. It does not run a circuit, produce another core baseline, replay XML, execute Native code or measure energy. The root integrator approved one invocation of producer `8c79c7eb`; its [separate receipt](../performance-evidence/jfr-privacy-smoke-001/README.md) records a real PASS. The producer's original preparation commit and sources remain unchanged.

`scripts/performance/smoke-jfr-privacy.py` defaults to a dry plan. With `--execute`, it permits one new output directory and one Java source-launcher process, with a 30-second timeout and no retry. The source launcher compiles the small Java helper internally; there is no separate javac or Gradle process. Sources, the Java launcher, copied helper and copied JFC are hash-checked before/after. The producer must remain at the approved clean Git revision.

The Python parent fixture is declarative and contains only fixed runtime/locale/temp values and fake credential/Java-option sentinels. The driver does not read inherited environment values. It derives the allowed key names from the frozen runner's literal `JAVA_ENVIRONMENT_KEYS` and supplies that filtered dictionary explicitly to Java. The execution shell should additionally use `env -i` to avoid giving even the Python parent real credentials. No environment values are printed or stored in the plan or receipt.

The Java helper requires exactly the named, running startup recording. It does not create a fallback. It checks that the three sensitive event settings are disabled, that the fake credential/option variables are absent, and that injected option properties are absent. It enables and commits one custom event without fields or stack, then performs `stop`, `dump` and `close` before decoding the file with the official `jdk.jfr.consumer.RecordingFile` API in the same JVM. It counts actual event records, rather than event types listed in metadata.

Acceptance requires exactly one marker, zero `jdk.InitialEnvironmentVariable`, `jdk.InitialSystemProperty` and `jdk.JVMInformation` events, absent fake sentinel bytes, absent option properties, matching source identity and exit 0. CPU/allocation event counts are observations; a short smoke is not required to produce those samples. JSON contains event names, counts and booleans, not event fields or environment values. Failure artifacts remain literal in the new output directory. No subsequent JVM is needed to decode the recording.

The local JDK 21 source archive supplies the owning API definitions: `jdk.jfr/Recording.java` documents stopping, dumping and closing; `jdk.jfr/consumer/RecordingFile.java` documents `hasMoreEvents` and `readEvent`; `jdk.jfr/Event.java` documents commit. Static review, Python syntax/source checks and a dry plan preceded the approved invocation. The subsequent real smoke parsed the JFC, compiled the source internally and decoded the closed recording; it observed one marker and zero sensitive events. This is not a repeat of the core timing workload.
