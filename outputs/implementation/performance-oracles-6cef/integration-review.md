## Finding

**P2. The first `input_change` sample repeats the input when `warmups` is odd.** In `CircuitPerformanceBenchmark.kt:85`, warmups use zero-based indices. At `:86–87`, sample indices restart at zero. The operation sets `lastInputHigh = iteration % 2 == 0` at `:117–119`. With `warmups=1`, setup uses low, the warmup uses high, and the first sample repeats high. The check at `:121–122` correctly expects a high output, but the sample measures an unchanged input under the `input_change` label. This occurs with any odd warmup count allowed by `:63`. With zero or an even number of warmups, including the documented example with two, the first sample measures a transition.

The defect already existed in baseline `6cef`, before the operation and verification were separated. For an accepted configuration, it contradicts the unconditional statement that “input_change alterna a entrada” (input_change toggles the input) in `docs/performance-hosts.md:29`. The approved minimal fix is to replace index-based selection with `lastInputHigh = !lastInputHigh` on each call. The same variable then tracks the applied value, and every operation changes the input, including the first measured sample. The fix is compatible with the phase filter and `unchanged_settle`.
